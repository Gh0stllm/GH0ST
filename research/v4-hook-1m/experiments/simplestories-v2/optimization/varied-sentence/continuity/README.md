# Story continuity across swaps — local experiment

Status: **the selected Relative64 implementation passed 2,060 consecutive local PoolManager swaps**, producing 2,073 tokens with exact independent-reference parity on every turn. Maximum whole-swap execution gas was **28,423,709** under a 32,000,000 transaction limit. The stream crossed the former 2,048-position boundary without resetting. Earlier variants and their limitations are preserved as research evidence. No public-chain transactions were submitted.

The independent-sentence baseline in the parent directory generated each output from the same quotation-mark prompt. Its 10,000 distinct-output proof does not establish story continuity. This experiment instead carries actual model state from one swap into the next.

## Selected behavior

Each pool has its own evolving story. The next model step consumes the prior generated token and the retained attention keys/values. The selected adapter generates up to two new tokens while at most 26 positions have been processed, then one token per swap. Native punctuation/EOS can end a turn early. A sentence therefore spans several swaps. The interface must show the accumulated story and must not label every short addition a complete sentence.

The numerical state is append-only data computed by the model. Users can supply a sampling seed but cannot replace the attention state with arbitrary bytes or choose a finished response from a table. The model's 1,235,968 learned parameters remain unchanged. Direct attention covers the latest 64 positions, including the current position; older computed history is no longer directly attended to.

`kernel/SimpleStoriesV2Relative64Model.sol` stores raw keys and values, leaves each query unrotated, and rotates keys by their relative age from zero to 63. This removes the earlier 2,048-position lookup limit without resetting the prompt. Relative rotary attention has the same real-number identity as absolute rotary attention, but Q12 rounding differs; this variant has a separate independent integer reference. The 64-bit counters still have their ordinary finite integer bound.

Only active inference is bounded to 64 positions. Historical data contracts and their references accumulate on-chain, paid for as each turn is created. This is not bounded total chain storage.

A preview is tied to the current pool revision and context hash. If another swap advances the story before submission, the stale transaction must reject rather than silently produce a different continuation. Failed swaps must roll back both the trade and story state.

The fixed-seed stream advanced actual numerical state, pending tokens, and the global sampling step across every successful swap. Native EOS occurred six times and did not trigger a software reset. The independent relative-Q12 reference also includes full-prefix numerical checks at positions 2,047, 2,048, 2,049, and 2,050.

Stale revision/context and forged context were rejected, as were malformed hook data, unauthorized callbacks, changed model runtime, and tampered active history. A forced router revert after inference rolled back both the trade and story state. Other callers and pools remained isolated. These checks and receipt gas are recorded in [the final v4 evidence](relative-benchmark/README.md).

The test used one fixed seed, test ERC-20s, and an unforked local chain. It does not establish a worst-case gas limit for every possible evolving story or live Robinhood fees. Data runtimes were hash-checked and injected to save setup time; their deployment costs are excluded. Every persisted story update was generated by an actual successful local swap.

## Earlier variants and quality limits

The earlier full-attention prototype accumulated more work as context grew. Adaptive token limits and then an absolute-position rolling window were tested, but the absolute rotary table retained a 2,048-position lifetime limit. Those sources, failed cases, and reports remain comparison evidence. Relative64 is the selected implementation; its different Q12 rounding is intentional and separately verified.

The generated text can repeat words, introduce inconsistent characters, and drift into new vignettes. A retained 64-position attention window does not guarantee permanent memory or an indefinitely coherent plot. Native punctuation is genuine model output; a token cap does not manufacture a completed sentence.

The independent 10,000-output catalog remains separate evidence for a decoder that restarts from its prompt. It does not prove 10,000 unique or grammatical continuations for every evolving Relative64 state.
