# Source06 · bounded production transport

**Host-only candidate. Ordinary source06 node and validator builds and configuration-only smokes passed; production activation and mainnet execution remain unaccepted.** The selected guest, machine, engine, model and current source03 dispute are unchanged.

This seven-file overlay adds a validated request cap, the tested shared upload gate and fail-closed startup checks to source05. The server setting is `validation.rpc-request-max-bytes`, default **3,221,225,472 bytes**, accepted only in the range 1–3 GiB and when representable by the host HTTP integer. Both entry points apply it after generic HTTP/WS/auth configuration and before constructing the Geth stack.

The standalone validator intentionally changes from unlimited request values to a finite 3 GiB default even when the cache is disabled. With embedded validation, this is a **shared stack** limit and also applies to other HTTP/WS listeners in that stack. An ordinary node without embedded validation keeps its previous limits. Authentication, loopback binding and external ingress limits remain separate settings.

The enabled operator profile cold-enables one process-global upload slot on every paired RPC client. Both validation and execution-creation callbacks acquire before converting input to JSON and hold the slot until the RPC response/error. Waiting cancellation does not release another caller's lease. Every call captures its policy once. The default remains off. This bounds opted-in conversion/upload callbacks; it does not bound typed-key copies, queued input memory, native machines, other processes or bypassing callers.

Enabled startup requires an explicit nonzero 32-byte hexadecimal `node.block-validator.current-module-root`. It checks the actual parent root against that same value and checks every started RPC client's advertised support before enabling its BOLD cache. Valid non-latest roots work. Errors roll back only startup-owned resources using source05's reviewed cleanup. Disabled startup retains its previous compatibility log/continue behavior.

The intended private profile uses WARN, `validation.use-jit=false`, authenticated loopback validation, the 3 GiB cap, source03's serialized/refining execution cache and five-minute server expiry. WARN avoids the known lazy client payload formatter. Geth's eager error-data formatter is unchanged; there is no global formatting/allocation guarantee. Coordinated endpoint/secret/machine-collection locations and an upload/query deadline policy still require final configuration review.

Focused evidence covers genuine small authenticated HTTP and fragmented WebSocket requests; client admission across both methods and instances; cancellation, RPC failure, default opt-out and idempotent release; each-client root support, non-latest support and rollback; ordinary typed configuration plus validation; standalone invalid caps; and an actual loopback `eth_call` parent-root helper. These tests perform no chess search, proof replay or financial operation. Configuration dumps are not used as startup or validation evidence.

The first combined main-package race build was stopped at the six-billion-byte disk floor before any tests ran. Its actual `-15` exit, 134.83-second duration, temporary-file inventory and cleanup receipt are retained. A single authorized sequential retry uses the warmed cache, one build worker and the same guards. The authorized sequential retry passed for both entry points (8.359 seconds for node, 4.223 seconds for validator). All 23 top-level tests and 50 subtests passed in normal and race runs. The original resource stop remains distinct and preserved.

Both ordinary entry points were built with the frozen seven-file overlay. The node build exited zero in 11.9165 seconds; validator exited zero in 9.2674 seconds. Both have a non-executable stack and bind the same unchanged selected865 machine/model. The ordinary dependency audit selected 6,204 source records, with exactly seven host-file changes/additions from source05. See `../ordinary06/` for the combined lock and actual build/smoke receipts.
