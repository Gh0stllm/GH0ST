# Independent quality review

The pinned optimized engine showed **no identified arithmetic, indexing or search-policy weakening** in this bounded review. This is supported by source analysis, exact parameter inspection, actual Wasm arithmetic tests and saved native-equivalence evidence. It is not a proof covering every chess position or a prediction that nobody can win.

The selected engine remains `725dc0c795262be21f1ffafec60f50aae3e9d00140add77e791a89eece0f417b`. Independent inspection found the exact98,511,183-byte pinned NNUE in its initialized Wasm memory and verified the frozen baseline hash is unchanged. Only the upstream yield insertion, sparse affine implementation and SIMD tiling header differ from the prepared baseline; the game adapter, dense affine layers and network load/save code remain unchanged.

The new sparse matrix is a derived representation of the same signed-i8 weights. It sign-extends them into paired i16 arrays when each of the eight network buckets loads. The activation range is0..127, so a pair's extreme sum is−32512..32258: the original saturating i16 operation never saturates. Two standard signed integer dot operations and wrapping i32 additions therefore preserve the original four-product result. Every one of the pinned1024×32 matrix's32,768 weight coordinates was checked against upstream scrambled indexing. Wasm little-endian input extraction and four-output lane ordering agree.

The existing arithmetic Wasm was independently reexecuted for the four recorded seeds plus zero seed:5million output comparisons, no mismatch. Four million repeat the earlier random coverage; the extra zero seed is deliberately degenerate, not another million independent random cases. The unit checks full-u32 accumulator wraparound and every activation pair against endpoint weight pairs. It tests local four-output arithmetic; source mapping and complete searches supply additional integration evidence.

Tiling32 changes the number of independent accumulator lanes processed per loop. Existing dimension-divisibility assertions remain, and per-lane feature arithmetic/order is preserved. Selected build options leave the rejected generic-dot experiment disabled. The generic dense affine path was not altered or assumed to have the sparse broadcast layout. No relaxed SIMD, fast-math flag or indirect-call Asyncify shortcut is selected.

Saved actual PocketIC execution matches the same retained native process twice: **e7e5/24,000,033nodes/depth38**, then **b8c6/24,000,311nodes/depth39**. The engine harness begins at the post-e4 FEN; the separate14-check coordinator integration also verifies the standard initial FEN with the complete e2e4 history. The24m-node allowance, Hash128, full NNUE, maximum skill and retained histories remain intact. Adaptive slicing resumes the existing search rather than resetting it.

The maximal-journal test uses a separate test-only module and completes two real slices under the40B instruction cap. Its approximately30.35B recorded figures are cycle debit including persistence/reply; the measured instruction counter before persistence is approximately28.02B. This supports headroom for the tested shape, not a universal worst-position bound.

No source correction is required by the findings above. The specialized sparse loop relies on the pinned input dimension being divisible by256; future architecture changes need a fresh dimension/range review. Public-network move latency remains unmeasured, and6.86times fewer updates must not be described as6.86times faster play. No new inference was run for this review.
