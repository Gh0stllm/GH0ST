# Exact retained-state checkpoint research

**Read-only candidate audit. No serializer, restored-search equality proof, production cache, or cost saving has been implemented here.** The isolated optimized engine's exact integer kernels and instruction-budget slicing take priority. Neither the pinned native source/binary nor the baseline/optimized ICP engine was changed by this audit. `source-audit.json` fingerprints the inspected SF19 source.

An exact opening-prefix cache could reuse a previously completed search and its entire retained state when a later game reaches the identical prefix from the identical prior engine state. This would be disclosed as checkpoint reuse, not fresh inference. A FEN-only lookup or a stored best move cannot preserve the retained policy.

## State that a future serializer must account for

The following inventory applies to upstream commit `edb0d9db6731067ec50ce619ff372b463bc4dd5d`, one thread, one NUMA partition, full pinned NNUE, Hash128, fixed24m nodes, maximum skill, no pondering or tablebases. It is a source audit, not a completed proof that every field below is necessary or sufficient.

| Owner | Mutable state | Boundary treatment / evidence |
| --- | --- | --- |
| `TranspositionTable` (`tt.h`, `tt.cpp`) | Every32-byte cluster and packed10-byte entry; `clusterCount`; `generation8` | Preserve logical entries and generation. `new_search()` advances generation, and replacement/secondary aging use it. Serialize values, not the `table` pointer; verify exact size/layout/schema. Hash assignment calls `resize()` and clears TT even when unchanged. |
| Worker (`search.h`, `Worker::clear`) | `mainHistory`, `captureHistory`, `ttMoveHistory`, `continuationCorrectionHistory` | Persist. `mainHistory` is decayed at the next iterative-deepening entry; restoring after that decay would apply it twice. These alter ordering, reductions and evaluation correction. |
| SharedHistories (`history.h`) | Dynamic `correctionHistory`, dynamic `pawnHistory`, all `[2][2]` continuation-history tables; logical table sizes | Persist logical atomic values. Reallocate at the identical one-thread size, then restore contents. The Worker holds references into these allocated objects, so raw Worker bytes would contain invalid addresses. |
| Worker `lowPlyHistory` | Search ordering statistics | Refilled102 at every `iterative_deepening()` entry. A between-search checkpoint can rebuild it at that same boundary; do not assume this applies to a mid-search snapshot. |
| SearchManager (`search.h`, `thread.cpp`, `search.cpp`) | `bestPreviousScore`, `bestPreviousAverageScore`, `previousTimeReduction`, `originalTimeAdjust`, `callsCnt`, `iterValue`, TimeManagement state | Preserve conservatively in an initial prototype; only omit fields after tracing all uses under fixed-node policy and proving exact future decisions. `iterValue` is overwritten from `bestPreviousScore` at search entry. Score/average are written on search completion. Time-control branches are disabled by this policy, but that alone is not a full omission proof. |
| Worker root/search fields | `rootMoves` including previous PV/score/average/effort; `rootDepth`, `rootDelta`, `optimism`, `lastIterationIdxPV`, node counters, depth/index fields, `limits`, `tbConfig` | `ThreadPool::start_thinking()` creates fresh legal root moves and resets nodes/tbHits/bestMoveChanges/nmpMinPly/rootDepth, assigns limits and tablebase config. Aspiration sets optimism/rootDelta before root search; last PV is updated per iteration. Rebuild at the precise pre-search boundary, after proving no stale value is read before overwrite. Never serialize an in-flight recursive Stack/PV by address. |
| Position and history (`Engine::set_position`, `ThreadPool::start_thinking`) | Engine position, full StateInfo chain, rootState | Rebuild from the standard initial FEN and **complete UCI history**. Position FEN omits repetition history, pliesFromNull and other StateInfo details; source explicitly restores rootState from the full deque. Relocate every `previous` link. Verify independent native-board/transcript commitments. |
| NNUE `refreshTable` (Finny caches) | Per-square/per-color feature accumulations, PSQT sums and cached bitboards | Candidate recomputable cache, **not yet proved safe to discard**. An initial exact prototype should preserve values and valid metadata; any fresh-cache alternative needs integer-arithmetic reasoning and consecutive full24m equality tests. Network pointers/weights are reattached by pin, never copied as process pointers. |
| NNUE `accumulatorStack` | Dirty-feature and computed accumulators, stack size | `Worker::start_searching()` calls `reset()` every search. A between-search snapshot should enter through the same reset and reconstruct current features. A mid-search checkpoint additionally needs complete stack and suspended Wasm runtime, outside this candidate. |
| ThreadPool / Engine | Stop/increaseDepth/ponder flags; allocated workers; `setupStates`; options; network; thread/update callbacks | Reconstruct allocations/callbacks and the full-history deque, then explicitly enter the same idle pre-search state. Pin options/network/source/module/architecture. No raw Engine, Thread, `unique_ptr`, reference, mutex, function object, or vtable image can be imported into a fresh native process. |

## Gate before any implementation claim

1. Use a separate source copy and test-only serialization interface. Save only while the single worker is idle after a committed completed decision; never from an unfinished search.
2. Define a versioned bounded encoding with explicit byte order, logical array dimensions, build/policy/module identity, checksum and pre-state digest. Reject truncation, trailing data, wrong NNUE/hash size, impossible generation and mismatched prefix before mutating live state. Restore transactionally into an unused engine.
3. The lookup key must bind full policy and code identity, initial FEN, complete move prefix, and the entire incoming retained-state digest. Identical board FEN is insufficient, including across games with different prior search paths.
4. Compare original retained execution against a new process initialized at the same full prefix and restored checkpoint. Require **2–3 consecutive future decisions** at full24m with exact bestmove, actual nodes, depth and final retained-state digest. Include a transposition/repetition counterexample, different-prefix rejection, checksum corruption and deliberate omitted-history tests. No equality proof has run yet.
5. Only after native equality passes should an isolated ICP prototype measure stable-memory restore/checksum/journal cost against a fresh24m search. No production cache, smaller search or alternate opening book is authorized by this research.

This candidate might save real inference cycles on repeated identical openings, but storage, hashing, restoration and cache coverage can outweigh savings. No saving or quality equivalence is claimed until measured.
