# Immutable paged model registry

`Gh0stModelRegistry.sol` stores model pages separately from Stylus Wasm code and seals a registered Merkle commitment only after every authenticated page is present. It is a local EVM data-integrity prototype, not an LLM loader or an activated GH0ST L3 component.

## Exact commitment format

The model identifier is:

```
keccak256(abi.encode("GH0ST_MODEL_V1", owner, root, uint64(totalBytes), uint32(pageBytes), declaredFileSHA256))
```

For zero-based page index `i` and exact page bytes `p`:

- Real leaf: `keccak256(0x00 || uint32_be(i) || uint32_be(length(p)) || p)`.
- Parent: `keccak256(0x01 || left32 || right32)`.
- Padding leaf: `keccak256(0x02)`.
- Pad to the next power-of-two leaf count with that constant padding leaf. Sibling proofs are bottom-up; index bits choose left/right order.

The final real page's proof must contain the canonical empty-subtree hashes for every fully padded right sibling. This prevents registration of an arbitrary padding root that could otherwise pass all real-page proofs.

Registration accepts power-of-two page sizes from 256 to 65,536 bytes, at most 1,048,576 pages, and at most 64 GiB declared model bytes. These are **format bounds**, not measured storage capacity or affordable deployment claims. The file SHA256 is committed metadata; the contract does not concatenate every page to recompute it. A future loader must independently check the expected model identity and full-file hash. Registration by an owner is not proof of model provenance or safety.

Only the registering owner can upload or seal. Valid pages may arrive out of order; their authenticated indices and lengths prevent content reordering. Conflicting duplicates revert, identical duplicates do not change counts, missing pages prevent sealing, and no mutation/delete/replace API exists. Pages become readable through `getPage` only after sealing. Identical upload/seal/register requests remain idempotent after sealing.

## Local verification

```sh
node test.mjs
```

This compiles Solidity 0.8.30 with optimizer/viaIR and a Shanghai target, deploys to an in-memory Ganache chain31337, and submits real local EVM transactions. Eighteen checks cover metadata binding, registration idempotency, limits, authorization, unknown models, wrong proofs/content/index/length, canonical padding, sealing and immutable reads. The main fixture has 1,025 bytes in five pages; an extra single-page fixture exercises a zero-height Merkle tree. No public RPC or wallet is accessed.

`evidence/registry-tests.json` contains local receipts/gas, bytecode hash and scope. `evidence/fixture.json` provides the exact bytes, Merkle proofs and root for independent reproduction. The test wallets are generated by the local simulator and never fund any public transaction. The optional native µWS warning on this Mac causes Ganache to use its JavaScript transport implementation; EVM assertions still execute.

## Remaining integration

The native/Wasm model loader is not connected to this registry, no large model was uploaded, and the full-file SHA has not been checked inside an on-chain execution path. Large page storage can be expensive; local small-fixture gas is not a public-chain or multi-gigabyte cost estimate. Parent-root anchoring, content availability/finality, model-reader authentication and matching inference/fraud-proof execution still need integration and testing.
