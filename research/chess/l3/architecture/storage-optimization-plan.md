# State access release gate

This is a source-reviewed optimization plan, **not implemented or benchmarked savings**. The current real A12 fixture measures 245,844,125 gas for one advance under an oversized local allowance. Native compilation preserves the tested outputs and gas; it does not solve storage pricing. No ordinary-transaction or twenty-game cost claim follows from the developer build.

The guest and its exact INT8/Q12 arithmetic can remain unchanged for these two steps:

1. **Write only changed checkpoint words.** Compare the newly exported canonical checkpoint against the authoritative bytes already read during restore. Preserve its complete SHA256, expected-generation guard, caller identity, zero transitions, final-word padding and atomic checkpoint/metadata update. Use only transaction-local knowledge: no process cache may supply future-affecting state. Skip implicit zero words at first creation only when absence is authenticated. Compare every checkpoint and final state root against the existing implementation, and repeat failure/rollback tests.
2. **Read immutable model code chunks instead of storage words.** The 4,401,034-byte model needs approximately 180 chunks at 24,575 data bytes plus a STOP prefix per contract. Commit ordered addresses, lengths and code hashes; reject missing, changed or reordered chunks, and retain complete model SHA256 verification. Every byte must be published through chain data availability and available to replay/proving. Meter account access, copying and hashing. The current Solidity registry's `bytes` pages still use storage and do not remove this read cost by themselves.

At the pinned ArbOS source tariffs, model-word reads alone are roughly 110.03 million gas. Full checkpoint restoration still reads 22,829 words, roughly 18.26 million gas. A maximum phase-10 batch can modify 1,024 words, roughly 20.48 million write gas before computation. These are source-derived estimates, not new runtime measurements. Neither optimization alone establishes that the existing maximum batch fits an ordinary transaction.

After implementing and measuring both changes, choose bounded batches using phase/context-aware deterministic pricing. Do not silently increase public limits or treat the debug computation floor as a complete tariff. Lazy state paging or replacing the checkpoint with Merkle roots would change loader/checkpoint semantics and require fresh native/replay/prover evidence. A complete incorrect-result fraud challenge remains mandatory before production assets.
