# State access release gate

The transaction-local dirty-word implementation is now verified in the experimental debug ABI. The immutable-code model reader and further paging/pricing work below remain a source-reviewed plan, **not implemented or benchmarked savings**. The original real A12 fixture measured245,844,125gas for one advance. Dirty filtering lowers that measured advance to132,053,125gas; full fixture gas including failure probes drops29.16%, with identical tested final state roots. Neither is an ordinary-transaction result, and no CPU speed improvement is claimed. Native compilation preserves the tested outputs and gas; it does not solve storage pricing. No ordinary-transaction or twenty-game cost claim follows from the developer build.

The guest and its exact INT8/Q12 arithmetic remain unchanged for the first step; the second remains planned:

1. **Implemented: write only changed checkpoint words.** Compare the newly exported canonical checkpoint against the authoritative bytes already read during restore. Preserve its complete SHA256, expected-generation guard, caller identity, zero transitions, final-word padding and atomic checkpoint/metadata update. Use only transaction-local knowledge: no process cache may supply future-affecting state. Skip implicit zero words at first creation only when absence is authenticated. Compare every checkpoint and final state root against the existing implementation, and repeat failure/rollback tests.
2. **Planned: read immutable model code chunks instead of storage words.** The 4,401,034-byte model needs approximately 180 chunks at 24,575 data bytes plus a STOP prefix per contract. Commit ordered addresses, lengths and code hashes; reject missing, changed or reordered chunks, and retain complete model SHA256 verification. Every byte must be published through chain data availability and available to replay/proving. Meter account access, copying and hashing. The current Solidity registry's `bytes` pages still use storage and do not remove this read cost by themselves.

At the pinned ArbOS source tariffs, model-word reads alone are roughly 110.03 million gas. Full checkpoint restoration still reads 22,829 words, roughly 18.26 million gas. A maximum phase-10 batch can modify 1,024 words, roughly 20.48 million write gas before computation. These are source-derived estimates, not new runtime measurements. Neither optimization alone establishes that the existing maximum batch fits an ordinary transaction.

After implementing and measuring both changes, choose bounded batches using phase/context-aware deterministic pricing. Do not silently increase public limits or treat the debug computation floor as a complete tariff. Lazy state paging or replacing the checkpoint with Merkle roots would change loader/checkpoint semantics and require fresh native/replay/prover evidence. A complete incorrect-result fraud challenge remains mandatory before production assets.
